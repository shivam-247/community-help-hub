# Community Help Hub privacy, content and accessibility review

Reviewed 10 October 2026. This is an engineering audit and issue register, not a legal opinion, compliance certificate or guarantee against litigation. Indian applicability depends on the actual operator, commercial activity, users and processing. An Indian lawyer must review launch arrangements and the policy drafts. No real payments are enabled.

## Shipped changes

- Public `/privacy`, `/terms`, `/cookies`, `/refunds`, `/contact`, `/accessibility` pages, footer links and account rights-request instructions.
- Signup gives a standalone purpose notice, then three unchecked declarations: account processing, terms, age 18+. FastAPI rejects missing/false/outdated declarations, and stores current policy version and timestamp in an additive `AccountConsent` table. No DOB, raw IP or fingerprint is collected for this record. Existing accounts have not been retroactively marked as consenting.
- Name is described as display name; neighbourhood rather than full address. Phone/photo remain optional and phone sharing/email alerts are off by default. Contextual notices explain publishing and reference submission; no marketing is bundled with signup.
- Government-ID/certificate verification options removed in UI and API. Only society references accepted. Free-text fields can still receive sensitive data: moderation and response procedures remain essential.
- Replaced the static image mount with an authorised endpoint: unattached uploads owner/admin only; private-post photos board members/owner/admin; selected avatars and public-post photos public. Filename validation and no-store responses apply even directly at the API. A photo intentionally reused as a public avatar/public notice is public.
- Removed unsupported “Most popular” claim. Samples are identified as fictional in cards and profiles. Sample credits/counts reset to zero on demo startup, so example badges cannot masquerade as earned reputation. Old `seed.py` now delegates to labelled sample seeding and never fabricates reviews or verified accounts. No live real-member reviews were deleted.
- Photo context alternatives, labelled response/review/admin controls, pressed state and names for rating buttons, persistent focus, skip target focus, stronger control boundaries, corrected light muted text and dark button contrast.
- Preserved installed Lucide ISC and Noto OFL licences in `THIRD_PARTY_NOTICES.md`. No stock photos or downloaded copyright images were found. Member upload rights cannot be verified by code alone: instructions, reporting and takedown review are required.

## Cookies, tracking and processors

Source audit: no Google Analytics, Vercel Analytics package, pixels, advertising, map/video frames or externally loaded fonts. Fonts are bundled. CSP restricts connections/images to self, and there are no embeds. Society analytics are server-side counts. Next.js build tooling may emit its own development/build telemetry; that is distinct from visitor analytics.

Production cookie `__Host-chh-session`: HttpOnly, Secure, SameSite Strict, path `/`, 3600 seconds; cleared on logout. Development name is `chh_session`. `chh-theme` is a device-local preference until cleared. Legacy `chh_token` is removed by existing auth code. No optional tracking therefore no optional-cookie banner was added. This is an implementation-specific decision, not a universal legal exemption: reassess country targeting, new trackers/embeds and hosting dashboard injections before launch. Nonessential tracking must not load first and ask permission afterwards. If introduced, provide equal reject/accept, purpose-level choices, withdrawal and gating for every tracker/SDK.

Vercel and Render process network/operational data; Render has used Singapore. Provider processing agreements, subprocessors, cross-border constraints and actual provider log retention require review. SMTP is not configured; update disclosures with the chosen delivery provider before enabling email. Never claim all data stays in India.

## Current Indian source review

- DPDP Act commencement: MeitY G.S.R. 843(E), 13 November 2025, separates immediate institutional provisions, one-year provisions and operational provisions after eighteen months. Rules G.S.R. 846(E) have the corresponding phased schedule. As of this review date, do not falsely say every DPDP duty is already operative or disregard readiness. Recheck notifications before launch. Build clear purpose notices, minimal processing, consent evidence, withdrawal, requests, processor safeguards and an incident response process. See [Act commencement](https://www.meity.gov.in/static/uploads/2025/11/c56ceae6c383460ca69577428d36828b.pdf) and [Rules](https://www.meity.gov.in/static/uploads/2025/11/53450e6e5dc0bfa85ebd78686cadad39.pdf).
- IT Act / SPDI Rules 2011: passwords fall within sensitive information. Review present applicability, privacy/consent, retention, security, grievance officer and international transfer safeguards during the DPDP transition. [Government text reproduced by WIPO](https://www.wipo.int/wipolex/en/legislation/details/15063).
- User-generated posts/messages mean intermediary obligations may apply, independent of paid subscriptions. Review current IT Rules (including 2025/2026 changes), the grievance mechanism, appeals, urgent unlawful-content handling and preservation requests. A generic reporting button and mailbox do not prove due-diligence compliance. [MeitY consolidated rules](https://www.meity.gov.in/static/uploads/2026/03/0b576f2071694b52e4cd6bb1b6dfab1e.pdf). This register does not certify that this consolidation includes every later change.
- Consumer Protection Act/E-Commerce Rules and dark-pattern/misleading-ad rules need assessment if paid plans launch. Free help between neighbours does not automatically exempt the platform's paid service. Verify legal entity/eligibility, geographic address, phone, grievance officer and complaint handling, refund/cancellation/renewal, tax pricing and explicit checkout consent. Current 2020 rules include 48-hour acknowledgement and one-month redress. The official index also lists 2026 amendments; counsel should inspect the gazette and commencement before applying their updated requirements. [Official index](https://consumeraffairs.gov.in/pages/consumer-protection-acts), [2020 text](https://consumeraffairs.gov.in/public/upload/files/E%20commerce%20rules_1732703966.pdf), [2026 amendment](https://consumeraffairs.gov.in/public/upload/files/E%20Commerce%20Amendment%20Rules%202026_1789127949.pdf).
- CERT-In incident-reporting, time synchronisation and log-preservation requirements need an applicability and implementation review for the operator/service. Do not mistake transient rate-limit data for compliant security logs. Avoid blanket deletion commitments until legal preservation is defined. [Official directions and FAQ index](https://www.cert-in.org.in/Directions70B.jsp).
- Copyright, privacy/defamation, prohibited goods and safety: require member rights to uploads, promptly review credible copyright/privacy reports and keep moderation evidence lawfully. Help requests can reveal health, addresses or children's data despite instructions. Avoid professional-service claims and sensitive documents. No photo audit can establish rights for every future upload.
- Accessibility: use WCAG 2.2 AA as the technical target, and obtain advice on applicable Indian disability/accessibility obligations. [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/). No conformance certification is claimed.
- If actively targeting people abroad, separately assess GDPR/ePrivacy, UK PECR or other local requirements; do not copy a foreign-law consent banner as proof of Indian compliance. [ICO storage guidance](https://ico.org.uk/for-organisations/direct-marketing-and-privacy-and-electronic-communications/guide-to-pecr/cookies-and-similar-technologies/).

## Unresolved launch risks and owner input

1. Confirm legal operator/status, business correspondence address, service phone and formally appointed grievance contact. Only known name/email are published; no address, GST/CIN or appointment was invented. Grievance/privacy mailbox must actually be monitored. Lawyer should determine which timelines apply and establish a working urgent response/appeal process, not just publish promises.
2. Durable database and image storage, backups, restore checks and retention/deletion tooling are still absent on ephemeral free Render storage. New consent records can be lost on restart just like accounts. Fix before relying on evidence or hosting real-member data.
3. Rights requests are operator-assisted email, not automatic export/erasure. Define identity checks, a request register, response deadlines, deletion/anonymisation across chat, reviews, communities, uploads, outbox and backups, and lawful preservation. Unattached/replaced uploads need an orphan cleanup policy. Existing verification records may contain legacy documents and need a purpose/retention review without blindly deleting evidence.
4. 18+ declaration is not verified age assurance and no parental consent system is implemented. Determine reasonable age assurance without collecting excessive documents; handle underage accounts safely. Do not claim children cannot register.
5. No real-payment launch under these test-only refund terms. Confirm legal entity, tax treatment, lawful refund rules, payment processor and reviewed commercial terms first. User consent to optional alerts is recorded as current preference, not a historical audit trail; delivery needs an unsubscribe flow and provider setup before use at scale.
6. Manual screen-reader, 200/400% zoom, mobile/device, dialog focus, error announcement and browser-network tracking tests remain needed. Automated token ratios do not prove image contrast or whole-site accessibility.
7. Audit any legacy database created by the old fabricated `seed.py` separately. The new release does not delete unidentified historical user reviews. Confirm old seed accounts/posts are removed or transparently marked with provenance before public launch.

## Verification and run instructions

Backend: `cd backend`, install `requirements-dev.txt`, set strong local JWT/MFA environment keys (tests generate their own), then `python -m pytest -q`. Frontend: `cd frontend`, `npm ci`, `npm test`, `npm run build`; use `npm run dev` for local checks. Existing `PRODUCT_UPGRADE.md` describes environment and startup. No new production secret is needed. Additive table creation runs at API startup; take a database backup before deploying to durable real-member environments.

Manual checklist: open every policy while signed out, follow footer and section links, test signup unchecked/keyboard focus/errors, confirm server rejects missing/outdated consent, submit only a reference, toggle theme, navigate rating controls and dialogs by keyboard, test public/private/unattached photos directly on Render and through the proxy, inspect network requests/storage for trackers, confirm mock checkout links policies and does not charge, review contact details and test privacy/copyright complaint handling. Check users with no old consent record are not described as having consented.

Automated validation completed: 56 backend tests and 11 subtests passed; 16 frontend tests passed (14 proxy, 2 theme contrast); Next production build passed. One Starlette/httpx test-client deprecation warning remains. Text-role token combinations tested at ≥4.5:1; control boundary tested at ≥3:1. This is not a whole-site accessibility certificate.
